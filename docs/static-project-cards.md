# 作品カードの静的化方針

## 現在の設計

作品名・説明・リンクを、JavaScriptを実行しない環境でも初期HTMLから読み取れるようにする。
ゲーム4件、ツール4件、メモ・記録2件の計10件のカードをindex.htmlに直接記述している。作品情報の唯一の管理先はindex.htmlであり、JSONとHTMLを二重管理しない。

app.jsはフッターの年号更新のみを行う。カード生成・データ取得・alert()による取得エラー表示はなく、移行元のassets/data.jsonは削除済み。ビルド工程やnpm依存関係は不要。

プロフィール、作品説明、通常カードの2 / 3 / 4列表示、メモ・記録の名称、SEO / OGP、README、ワークスペース名の整理は実装済み。これらを静的化の後続未実施タスクとして扱わない。新しい改善候補と進捗は[改善TODO](task-list.md)を参照する。

## 採用方式と理由

index.htmlにカードを直接記述する。10件という規模では、生成スクリプトや公開工程を増やすよりHTMLだけで管理する方が単純であり、作品情報も初期HTMLに含められる。既存のGitHub Pages向け静的構成を維持する。

## 方式の比較

| 観点 | index.htmlへの直接記述 | data.jsonからビルド時にHTML生成 |
| --- | --- | --- |
| 管理しやすさ | HTML編集が必要だが、10件なら更新箇所を把握しやすい | データはJSONに集約できるが、生成手順が必要 |
| SEO | 作品情報が初期HTMLに存在する | 生成済みHTMLを公開すれば同じ条件を満たせる |
| GitHub Pagesとの相性 | 既存の静的ファイルとして配信できる | 生成物の管理または公開前の生成工程が必要 |
| 保守性 | テンプレートの繰り返しはあるが、依存関係とビルド処理が増えない | カードの共通化は容易だが、生成スクリプトと実行環境の保守が増える |

## 現在の作品追加・更新手順

1. index.htmlのgames-section、tools-section、media-sectionから該当する一覧を選ぶ。
2. 新規追加は既存カードのcol要素全体を複製し、作品名、説明、href、画像パス、altを編集する。既存作品の更新は対象カードを直接編集する。
3. 新しい画像はassets/games、assets/tools、assets/mediaの該当ディレクトリへ置く。実在するパスとURLを使い、説明は根拠のある情報だけで記述する。
4. 既存の外部リンク属性（target="_blank"、rel="noopener"）と見出し構造を維持する。削除済みのassets/data.jsonを再作成しない。
5. コード変更の内容に応じて日本語の変更記録とdocs/task-list.mdの進捗を更新し、AGENTS.mdに従って改行・タブ混入・インデント・不自然なエスケープ文字をチェックする。
6. 作業ブランチでコミットし、PRを作成してSquash mergeする。コミットメッセージは「【概要】説明」の形式にする。

現在の作業方針では、ブラウザ表示・リンク遷移・公開設定・デプロイ後の動作確認を必須手順や独立したタスクに含めない。未確認の事項を確認済みとして扱わない。必要時のローカル確認方法は[README](../README.md)を参照する。

## 公開構成

ユーザーの共有事項により、このリポジトリはGitHub Pagesで公開されている。ルートにindex.html、styles.css、app.js、assetsがあり、CNAMEはrutile3.comを指定する。公開URLは[https://rutile3.com/](https://rutile3.com/)。

GitHub側の公開元ブランチ・ディレクトリ・デプロイ方式・独自ドメイン設定の詳細は、この文書では未確認。ローカルの構成だけから公開設定を推測しない。設定の調査が必要な場合はSettings → Pagesが参照先になるが、現在の必須タスクには含めない。

## 静的化の移行履歴

以下はfeat/static-project-cardsでの移行当時の記録。現在の作業ブランチやマージ条件を示すものではない。過去の詳細な変更記録は[仕様変更](spec_changes.md)に保持している。

### 当時の対応範囲

- 既存10件を初期HTMLへ転記し、移行時点の作品名・説明・画像・リンク・順序・CSSクラスを維持した。
- app.jsの描画呼び出しを停止した後、不要な生成・取得・alert処理とassets/data.jsonを削除した。年号更新は維持した。
- styles.css、CNAME、Google Analytics、Bootstrapの読み込み、既存URLは静的化では変更しなかった。
- HTML直接記述を採用したため、ビルド時HTML生成と生成手順の整備は対象外とした。
- originは`git@github.com:Rutile3/rutile3.com.git`、当時の作業ブランチはfeat/static-project-cardsだった。
- 当時、ローカルの追跡ファイルに独自のGitHub Actionsワークフローやビルド設定はなかった。GitHub CLIを利用できず、GitHub APIへの接続も失敗したため、GitHub側の公開設定は確定できなかった。
- マージ前のPC・モバイル表示、JavaScript有効・無効時の動作、リンクの開き方、公開設定と、マージ後の公開動作の確認を予定していた。現在は追加確認を必須としない。
