# 作品カードの静的化方針

## 目的と対象

JavaScriptを実行しない環境でも、作品名・説明・リンクを初期HTMLから読み取れるようにする。
対象はゲーム4件、ツール4件、メディア2件の計10件。作品説明の改善やデザイン変更は後続の作業で行う。
既存10件のカードはindex.htmlに直接記述済み。app.jsはフッターの年号更新のみを行い、カード生成とデータ取得は行わない。

## 公開方式の確認状況

- ユーザーの共有事項により、このリポジトリはGitHub Pagesで公開されている。
- originは git@github.com:Rutile3/rutile3.com.git。今回の作業ブランチは feat/static-project-cards。
- ルートにindex.html、styles.css、app.js、assetsがあり、CNAMEにはrutile3.comが記載されている。
- ローカルの追跡ファイルに独自のGitHub Actionsワークフローやビルド設定はない。ただし、これだけで公開設定は確定できない。
- この環境ではGitHub CLIが利用できず、GitHub APIへの接続も失敗したため、公開元ブランチ・ディレクトリ・デプロイ方式・GitHub側の独自ドメイン設定は未確認。

マージ前にGitHubのSettings → PagesでSourceを確認する。Deploy from a branchの場合はブランチとフォルダーを、GitHub Actionsの場合は公開ワークフローと配信対象を確認する。Custom domainがrutile3.comであることも確認する。
既存の公開設定は変更せず、その方式でルートのindex.htmlと関連資産が配信されることを確認する。公開元へのマージ後は、デプロイ成功と https://rutile3.com/ の表示を確認する。

## 方式の比較

| 観点 | index.htmlへの直接記述 | data.jsonからビルド時にHTML生成 |
| --- | --- | --- |
| 管理しやすさ | HTML編集が必要だが、10件なら更新箇所を把握しやすい | データはJSONに集約できるが、生成手順が必要 |
| SEO | 作品情報が初期HTMLに存在する | 生成済みHTMLを公開すれば同じ条件を満たせる |
| GitHub Pagesとの相性 | 既存の静的ファイルとして配信できる | 生成物の管理または公開前の生成工程が必要 |
| 保守性 | テンプレートの繰り返しはあるが、依存関係とビルド処理が増えない | カードの共通化は容易だが、生成スクリプトと実行環境の保守が増える |

## 採用方式

index.htmlにカードを直接記述する。現状の件数では、生成スクリプトや公開工程を増やすより、HTMLだけで管理する方が単純なため。
作品情報の唯一の管理先はindex.html。移行元のassets/data.jsonは転記後に実行コードの参照がないことを確認して削除済み。JSONとHTMLを二重管理しない。

## 実装状況

1. index.htmlに既存10件のカードを追加し、app.jsのカード描画呼び出しを停止済み。作品名・説明・画像・リンク・順序・CSSクラスを維持している。
2. app.jsの不要なデータ取得、DOM生成、alert()とassets/data.jsonを削除済み。フッターの年号更新は維持している。
3. コードの検証結果をdocs/spec_changes.mdに記録し、docs/task-list.mdを更新済み。ブラウザでの表示確認と公開設定の確認は未完了。

styles.css、CNAME、Google Analytics、Bootstrapの読み込み、既存URLは今回の静的化では変更しない。ビルド工程やnpm依存関係は追加しない。

## 移行後の作品追加・更新手順

1. index.htmlのgames-section、tools-section、media-sectionから該当する一覧を選ぶ。
2. 一覧内の既存カードのcol要素を複製し、作品名、説明、href、画像パスを編集する。既存作品の更新は対象カードを直接編集する。
3. 新しい画像はassets/games、assets/tools、assets/mediaの該当ディレクトリへ置く。実在するパスとURLを使い、説明は確認できた情報だけで記述する。
4. 外部リンクのtargetとrelを既存カードに合わせ、見出し構造とalt属性を確認する。
5. ローカルで表示・リンクを確認し、JavaScript無効時にも作品情報が表示されることを確認する。
6. docs/task-list.mdと該当する変更記録を更新し、作業ブランチからPRを作成する。公開元へのSquash merge後にGitHub Pagesのデプロイと公開表示を確認する。

作品の追加・更新は上記の手順でindex.htmlを編集する。削除済みのassets/data.jsonを再作成する必要はない。

## 確認項目

- 初期HTMLに10件すべての作品名・現在の説明（空の場合は省略）・リンクが存在する。
- JavaScript無効時にカードが表示され、有効時にも重複しない。
- 画像パス・リンク先・外部リンクの開き方が移行前と一致する。
- PC・モバイルのレイアウトを維持し、JavaScriptエラーがない。
- フッター年号更新とGoogle Analyticsの設定を維持する。
- HTMLの直接配信で動作し、追加の生成処理を必要としない。

公開設定の確認は未完了としてタスクリストに残す。採用方式と理由はPR・作業完了報告にも記載する。
