# rutile3.com リファクタリング・文書整理TODO

## 方針

リファクタリング・文書整理の未完了タスクを管理する。新しい作業はブランチ単位で整理し、その中の作業をコミット単位で記載する。

- タスク番号とコミット番号で作業を指定できる。削除済みの完了タスクの番号は、新しい作業に再利用しない。
- 各タスクにブランチ名とコミットごとの対応範囲・メッセージ案を記載する。コミットメッセージは「【概要】説明」の形式にする。
- 各コミットに必要な変更記録とTODOの進捗更新を含める。コード変更はAGENTS.mdに従い日本語で記録する。
- 表示・リンク・公開状態の確認専用タスクは追加しない。編集時の書式チェックと、対象コード・文書の読み取りは行う。
- 現在の表示・作品情報・リンク先・OGP・Google Analytics・JavaScriptなしでの主要コンテンツ表示を維持する。
- 完了項目は関連文書への反映後にTODOから削除する。履歴は変更記録とGitで管理する。
- devへの集約運用は検討段階。今回のTODO作成ではブランチ・公開設定を変更せず、採用決定前に文書へ確定手順として記載しない。

## 未完了タスク

現在、未完了のタスクはありません。完了項目はREADME・設計文書・仕様変更記録への反映を照合したうえで削除しました。

## 大きなリファクタリングを提案しない理由

- カードは10件で、静的HTML方式の採用理由が既に記録されている。重複だけを理由にJSON管理・JavaScript生成・テンプレートエンジンへ戻さない。
- app.jsは年号更新の1処理だけで、現在は年号要素のあるindex.htmlのみが読み込む。汎用化・関数分割・存在チェック追加を必須改修にしない。
- index.htmlと404.htmlの共通部分は少なく、共通化のためのビルド工程は追加しない。
- 変更記録は現在の規模で別アーカイブへの分割を必須とせず、過去の事実を要約・削除して失わない。
- 見送り済みの機能や、根拠のない配色・レイアウト変更は再提案しない。
